# 1.3.3 网络异常闪退修复

日期：2026-09-15。

1.3.2 启动后的网络异常处理存在确定性缺陷：在 PowerShell StrictMode 下读取普通异常对象不存在的 Exception 属性，二次报错逃出 WPF 回调，导致整个窗口退出。旧版本启动日志与独立复现一致。

1.3.3 改为安全读取可选属性，解包 ErrorRecord 和内部异常，并容忍未知错误对象。没有关闭自动更新，也没有忽略失败或把失败显示成成功。

已验证：

- 旧 1.3.2 运行新回归测试失败，证明测试覆盖原缺陷。
- 13 种错误输入通过，包括超时、取消、DNS、代理、TLS、拒绝连接、包装异常、未知对象和空值。
- 6 种失败通过真实 WPF Dispatcher 调用生产版核心更新完成函数，失败提示正确，任务清理及重试按钮恢复正常。
- 1.3.3 补丁安装、中文空格路径、文件占用回滚和损坏哈希拦截通过。
- 完整启动器窗口故障注入通过：自动请求超时后持续运行 20 秒，显示超时，恢复检查按钮并能切换页面。第一次测试注入缺少 HTTP 程序集，修正测试初始化后重新通过；不将第一次计为通过。
- 本地已安装 1.3.3 的普通启动器窗口连续运行超过 4 分钟，进程仍响应，bootstrap.log 未新增异常。此项不能代替其他操作的测试。

过去 Verify-Release 的 LauncherBoot 检查只验证 EXE 拉起 PowerShell，并使用休眠脚本作为探针；不能据此宣称真实界面自动检查流程通过。新增 Test-NetworkFailures.ps1 进入 Windows CI；Test-FullWindowNetworkFailure.ps1 用于装有完整整合包的机器，注入失败 HTTP 任务后运行真实窗口与事件循环，必须存活并能切换页面、恢复重试入口。

该版本只解决这次已确认的网络异常闪退，不代表其他显卡、第三方插件或所有工作流已经验证通过。此前记录的依赖冲突仍未解决。
