# 1.3.6 验证记录

日期：2026-09-30。范围：启动兼容、故障提示、启动器补丁和此前未公开的 1.3.5 改动。没有修改 Windows Null 驱动、安全策略或学员数据。

## 结论

本机已复现并处理“短名称 NUL 访问失败、完整设备仍可访问”这一分支。若完整设备也不可访问，启动器会提前停止并保留只读诊断，不能声称已经修复 Windows。原始反馈学员的电脑尚未复测。

| 已验证 | 方法与边界 |
|---|---|
| NUL 正常读写、短名称故障的设备路径回退、双路径缺失及权限错误 | `Test-Runtime.py`；只在 Python 进程内注入故障，没有停用真实系统驱动 |

| pip 和 Torch/dill 故障链 | `Test-RuntimeDependencies.py`：原方式两处报 FileNotFoundError；兼容路径下真实 pip 25.2、Torch 2.11.0+cu128、dill 0.3.8 通过 |
| 启动失败对话框 | `Test-StartupFailure.ps1` 调用生产结束处理逻辑：退出码 73、退出码缺失但有诊断标记、一般退出码缺失 |

| 网络故障和版本查询 | `Test-NetworkFailures.ps1`、`Test-GithubFallback.ps1`：HTTP 故障、官方页面回退、限流冷却、错误重定向拒绝和 WPF 完成回调 |
| 浏览器选择 | 设置保存、中文空格 EXE 参数派发、完整 WPF 选择/保存/打开/恢复默认回调，以及两种窗口尺寸的布局 |
| 后台进程及下载 | stdin EOF、实时输出、无换行尾行、双管道大量输出、超时退出、响应体停滞中断、后台 SHA-256 |
| 核心更新器自测 | 回滚、受保护数据、磁盘/归档路径检查、依赖差量与保护机制；不是一次最新内核联网升级 |

## 未验证与仍存在的问题

- 未在原始故障学员电脑复测，未模拟真实 Null 驱动损坏；故障注入只覆盖指定代码路径。
- NUL 路径兼容只作用于当前 ComfyUI 进程。独立 Python 子进程可能仍需进一步排查。
- 本次没有测试模型推理，没有保证所有第三方节点、GPU、系统与网络配置兼容。
- 独立副本首次省略空 output 目录引起部分插件加载/节点信息错误，已补上运行目录初始化并复测。未删除插件来隐藏错误。
- 本机第三方组件日志仍有 protobuf `MessageFactory.GetPrototype`、原生命令输出编码等警告；无模型基础流程可完成，不代表这些可选功能可用。
- 没有将已有的大型整合包 ZIP 或局域网副本替换为本次版本；本次交付为启动器补丁和源码。
